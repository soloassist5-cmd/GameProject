# План проекта игры

> Цель: сделать игру, которая по ощущениям, визуалу и отполированности стоит рядом с лучшими инди-хитами
> (Balatro, Vampire Survivors, Hades, Dead Cells, Celeste, Dredge, Slay the Spire, Mini Motorways, Alto's Odyssey).

---

## 0. Главный принцип: «маленькая игра — максимальный уровень качества»

Мировой уровень для маленькой команды — это не объём контента и не фотореализм, а:

1. **Одна сильная механика**, в которую интересно играть 100+ часов (core loop).
2. **Единый, узнаваемый визуальный стиль**, который можно сделать силами кода и шейдеров, а не армии художников.
3. **«Сочность» (game feel / juice)** — каждое действие отзывается звуком, анимацией, частицами, тряской, замедлением.
4. **Безупречная полировка**: 60 FPS, мгновенный старт, понятное обучение, ноль багов в первые 10 минут.
5. **Реиграбельность**: процедурная генерация, билды, синергии, мета-прогрессия.

Поэтому план строится вокруг правила: **сначала находим «фан» на сером прототипе, потом наращиваем красоту, и только потом — контент.**

## 1. Технологический стек (рекомендация)

| Слой | Выбор | Почему |
|---|---|---|
| Язык | **TypeScript** | Строгая типизация, быстрая итерация, легко тестировать |
| Сборка | **Vite** | Мгновенный hot-reload |
| Рендер 2D | **PixiJS 8** (WebGL/WebGPU) | Самый быстрый 2D-рендер в вебе, фильтры и шейдеры «из коробки» |
| Рендер 3D (если выберем 3D) | **Three.js** + постобработка | Стилизованное 3D (low-poly, toon, неон) |
| Физика (если нужна) | **Rapier** (WASM) | Детерминированная и быстрая |
| Звук | **Howler.js** + процедурные SFX (ZzFX/jsfxr) | Лёгкие звуки, генерируемые кодом |
| UI | Свой UI на Pixi или лёгкий DOM-оверлей | Полный контроль над анимациями |
| Тесты | **Vitest** (логика) + **Playwright** (скриншоты, смоук) | Автоматическая проверка, что игра запускается и выглядит как надо |
| Деплой | **Vercel** / itch.io (веб-демо) → **Steam** (через Tauri/Electron) → мобильные (Capacitor) | Одна кодовая база на все платформы |

Альтернатива: **Godot 4** — если хотим сразу нативный десктоп/консоли и редактор сцен. Но веб-стек даёт
самый быстрый цикл «написал → увидел → показал друзьям по ссылке», что критично для плейтестов.

### Архитектура кода
```
src/
  core/        # игровой цикл, фиксированный тик, ECS / системы, RNG с сидом
  game/        # правила игры: сущности, способности, враги, баланс (чистая логика, без рендера)
  render/      # спрайты, шейдеры, частицы, камера, постэффекты
  audio/       # музыка, SFX, адаптивный микс
  ui/          # меню, HUD, тултипы, экраны прогресса
  content/     # данные: JSON/TS-описания врагов, предметов, уровней
  save/        # сохранения, мета-прогрессия, миграции версий
  input/       # клавиатура, мышь, геймпад, тач — с переназначением
  debug/       # оверлеи, читы, профайлер, «песочница» баланса
tests/
docs/
```
Ключевые решения: логика отделена от рендера (можно гонять симуляции баланса без графики), детерминированный
RNG с сидом (повтор забегов, ежедневные челленджи), все данные контента — в декларативных файлах.

## 2. Этапы разработки

### Этап 0 — Концепция (≈1 неделя)
- [ ] Выбрать тематику и жанр (см. раздел 4)
- [ ] Сформулировать **3 столпа игры** (pillars) — то, ради чего в неё играют
- [ ] Описать core loop (секунды), session loop (минуты), meta loop (часы)
- [ ] Собрать мудборд: 20–30 референсов стиля, палитра, шрифты
- [ ] Одностраничный дизайн-документ (One-Page GDD)
- [ ] Определить целевые платформы и управление

**Результат:** понятно, что делаем и почему это интересно.

### Этап 1 — Прототип «поиск фана» (≈2–3 недели)
- [ ] Каркас проекта: Vite + TS + Pixi, игровой цикл, ввод, камера, дебаг-оверлей
- [ ] Core-механика на геометрических фигурах (серый бокс)
- [ ] 3–5 вариантов ключевой механики, быстрые A/B-проверки
- [ ] Первые плейтесты (5–10 человек), запись реакций
- [ ] Решение go / pivot / kill

**Критерий успеха:** в прототип хочется «ещё один забег», даже без графики.

### Этап 2 — Вертикальный срез (≈4–6 недель)
Один уровень/биом **в финальном качестве** — эталон для всего остального.
- [ ] Финальный арт-стиль: шейдеры, палитра, освещение, постобработка (bloom, хроматическая аберрация, виньетка)
- [ ] Полный пакет «сочности» (см. раздел 3)
- [ ] Музыка и звук для среза, адаптивная музыка
- [ ] Главное меню, пауза, настройки, сохранение
- [ ] Обучение, встроенное в геймплей (без стен текста)
- [ ] Стабильные 60 FPS на слабом ноутбуке и телефоне

**Критерий успеха:** 30-секундный ролик со среза хочется досмотреть и переслать.

### Этап 3 — Производство контента (≈2–4 месяца)
- [ ] Контент-пайплайн: добавление врага/предмета/уровня = новый файл данных, без правок движка
- [ ] 3–5 биомов/миров, 40–100 предметов/способностей, 20–40 типов врагов, боссы
- [ ] Система синергий и билдов
- [ ] Мета-прогрессия: разблокировки, персонажи, достижения
- [ ] Процедурная генерация с ручными «комнатами»/шаблонами
- [ ] Инструмент симуляции баланса (тысячи автозабегов без рендера)
- [ ] Регулярные плейтесты каждые 2 недели

### Этап 4 — Полировка (≈4–6 недель)
- [ ] Баланс по данным телеметрии плейтестов
- [ ] Доступность: переназначение клавиш, режим для дальтоников, масштаб UI, снижение тряски/вспышек, субтитры
- [ ] Локализация (RU, EN минимум; затем ES, DE, FR, PT-BR, ZH, JA, KO)
- [ ] Оптимизация: пулы объектов, батчинг, атласы, профайлинг
- [ ] Ачивки, облачные сохранения (Steam)
- [ ] Финальный аудио-микс

### Этап 5 — Маркетинг и демо (параллельно с этапами 2–4)
- [ ] Страница в Steam как можно раньше (вишлисты — главный показатель)
- [ ] Трейлер (первые 3 секунды — самое зрелищное)
- [ ] GIF/короткие видео для TikTok, Reddit, X, YouTube Shorts

## 3. Чек-лист «уровня мировых топов» (quality bar)

### Game feel / juice
- Hit-stop (микро-пауза 30–80 мс при сильном ударе)
- Тряска камеры с затуханием (trauma-based), с опцией отключения
- Squash & stretch у персонажей и объектов
- Частицы на каждое событие: удар, смерть, подбор, левел-ап
- Вспышки, мигание при уроне, всплывающие цифры урона
- Плавные кривые (easing) для всего UI — ничего не появляется «рывком»
- Звук на каждое действие, с вариациями высоты тона
- Слоу-мо на ключевых моментах (последний враг, крит, смерть босса)
- Отзывчивое управление: coyote time, буфер ввода, ускорение/торможение

### Визуал
- Ограниченная палитра (5–8 основных цветов) — единство стиля
- Читаемость: игрок, враги, снаряды и награды различимы с одного взгляда
- Постобработка: bloom, цветокоррекция, виньетка, лёгкое зерно
- Динамическое освещение/свечение
- Параллакс и живой фон

### UX
- От запуска до геймплея — меньше 10 секунд
- Перезапуск забега — одна кнопка, мгновенно
- Тултипы с понятными числами и ключевыми словами
- Поддержка геймпада с первого дня

### Техника
- 60 FPS стабильно, 120+ на мощных машинах
- Загрузка < 3 секунд
- Сохранения не теряются никогда (атомарная запись, версионирование)
- Автотесты на логику и смоук-тесты запуска в CI

## 4.1. Свежие концепции под тренды 2026

Что сейчас цепляет (по итогам 2025–2026):
- **Один крючок, который объясняется одной фразой.** Пример — Meccha Chameleon (2026): прятки, где ты раскрашиваешь себя под фон.
- **Кооперативный хаос с друзьями** (R.E.P.O., Peak, RV There Yet?): каждая сессия даёт смешные моменты, которые нельзя заранее срежиссировать, и их хочется нарезать на клипы.
- **Голос и микрофон как механика.** Голос по близости превращает игру в шоу для стримов.
- **Игры-компаньоны на рабочем столе** (Rusty's Retirement, Bongo Cat): игра живёт в углу экрана, пока ты работаешь.
- **Уютные «игрушки» без цели** (Tiny Glade, Townscaper): игроки делятся тем, что построили.
- **ИИ-персонажи, с которыми можно по-настоящему говорить.** В 2026 это уже технически реально, а нормальных игр на этом пока мало.
- **Резкая визуальная идентичность** вместо «красиво, но как у всех».

| # | Название | Фраза-крючок | Тренд | Почему зацепит |
|---|---|---|---|---|
| A | **«Тихий час»** | Кооп на 2–4 игроков: вы дети, ночью крадётесь по дому за печеньем. **Твой настоящий микрофон шумит в игре**, и громкий смех будит родителей. | Кооп-хаос + голос | Друзья давятся смехом, шепчут, кто-то чихает, и всех ловят. Идеальные клипы и стримы. |
| B | **«Эхо»** | Ты не видишь. Мир проявляется только волнами звука от шагов, броска камня, крика. Но то, что живёт в темноте, тоже слышит. | Визуальная идентичность + хоррор | Чёрный экран и светящиеся контуры, которые «рисует» звук. Делается чистыми шейдерами, на скриншотах не похоже ни на что. |
| C | **«Ты — алгоритм»** | Ты — лента рекомендаций маленького города. Удержи внимание людей любой ценой и смотри, во что превращается город. | Сатира на злобу дня | Тема касается каждого (думскроллинг). Моральный выбор в духе Papers, Please, споры в комментариях, отличные концовки. |
| D | **«Допрос»** | Подозреваемые — ИИ-персонажи со своими тайнами. Ты говоришь с ними свободно, текстом или голосом, ловишь на противоречиях и раскалываешь. | ИИ-нативный геймплей | Каждый допрос уникален, игроки соревнуются, кто расколол быстрее и хитрее. |
| E | **«Остров-мелодия»** | Строишь островок, и каждый объект добавляет инструмент: мельница — бас, маяк — мелодию. Остров звучит как твоя песня. | Уютная игрушка + шеринг | Остров можно отправить другу ссылкой, и он его и увидит, и услышит. |
| F | **«Город на панели задач»** | Крошечный город живёт по нижнему краю экрана и растёт, пока ты работаешь. Отвлёкся — его жителям становится скучно. | Компаньон на рабочем столе | Он всегда на экране, полезен для фокуса, а люди любят хвастаться своим городом. |

### Топ-3 свежих
1. **«Тихий час» (A)** — самый вирусный потенциал. Сложность в сетевом коде (WebRTC + сервер комнат), но это решаемо.
2. **«Эхо» (B)** — самый узнаваемый визуал при минимуме ассетов. Можно начать с одиночной игры, а позже добавить кооп.
3. **«Ты — алгоритм» (C)** — самый дешёвый в производстве, с сильнейшим высказыванием. Основа — UI, тексты и симуляция.

## 5. Топ-3 рекомендации

### 🥇 «Неоновый космос» (bullet-heaven roguelite) — тематика №1
- Стиль «светящаяся векторная графика + bloom» делается **полностью кодом и шейдерами** — без художников, а выглядит дорого.
- Жанр доказанно хитовый (Vampire Survivors, Brotato, 20 Minutes Till Dawn), низкий порог входа, огромная реиграбельность.
- Идеален для «сочности»: тысячи частиц, взрывы, слоу-мо.
- Риск: жанр конкурентный — нужна своя изюминка (например, корабль собирается из модулей-тетрамино, и форма корабля = билд).

### 🥈 «Казино-roguelike» (тематика №12) или «Алхимик» (№6)
- Самый высокий потенциал «ещё одной партии» (эффект Balatro).
- Минимум ассетов, максимум глубины через синергии; легко делать красиво за счёт UI-анимаций и CRT-шейдера.
- Риск: успех целиком зависит от баланса и гениальности системы комбинаций.

### 🥉 «Славянская мифология» (экшн-roguelite) — тематика №5
- Почти пустая ниша с сильным культурным колоритом и огромной аудиторией (СНГ + интерес на Западе после «Ведьмака»).
- Самый «вау»-потенциал в трейлере.
- Риск: требует больше арта и анимаций — сложнее и дольше остальных.

## 5.1. Альтернативный топ-3

### 🌊 «Океанская бездна» (рыбалка и менеджмент днём, ужас ночью) — тематика №9
- **Изюминка:** глубина = риск. Чем глубже закидываешь сеть, тем ценнее и страннее улов, но сильнее «давит» бездна:
  искажения экрана, ложные огни, твари из темноты. Улов можно продать, а можно «скормить» маяку, чтобы открыть новые воды.
- **Почему это сильно:** Dredge доказал, что жанр продаётся. Атмосфера держится на шейдерах воды, тумана и света фонаря,
  а их можно сделать кодом. Трейлер получается очень эффектным: спокойный закат, потом резкий ночной ужас.
- **Стиль:** вид сверху или изометрия, стилизованная вода, ограниченная палитра (бирюза, янтарь, чёрный).
- **Риски:** нужен сюжет и сильный звуковой дизайн. Ужас должен пугать, а не раздражать.

### 🪐 «Орбитальный садовник» (физическая головоломка / песочница с гравитацией) — тематика №19
- **Изюминка:** игрок не управляет объектами напрямую. Он ставит звёзды, планеты и чёрные дыры, и запущенная
  «искра жизни» должна по траекториям гравитации пройти через нужные миры. Пройденные планеты оживают и расцветают.
- **Почему это сильно:** почти всё делается кодом: светящиеся следы орбит, частицы, bloom. Каждый уровень — красивая
  «живая картина», которую хочется заскриншотить. Хорошо подходит для мобильных и коротких сессий.
- **Реиграбельность:** редактор уровней, ежедневные головоломки, обмен решениями.
- **Риски:** у головоломок ограничен объём контента. Нужен сильный дизайн уровней и редактор для сообщества.

### 🎵 «Ритм-roguelite» (всё движется в такт музыке) — тематика №13
- **Изюминка:** атаки, рывки и заклинания работают сильнее, если попадать в бит. Предметы меняют не только статы, но и
  саму музыку: добавляют инструменты, меняют темп и жанр. Каждый билд звучит по-своему.
- **Почему это сильно:** мир, пульсирующий в такт, — сильнейший «вау»-эффект в коротких роликах. Жанр на подъёме
  (Hi-Fi Rush, Rift of the NecroDancer, BPM).
- **Стиль:** неон или поп-арт, всё дышит в ритм: фон, враги, UI.
- **Риски:** в браузере нужна точная синхронизация аудио (решается через Web Audio API с компенсацией задержки).
  Музыка — ключевой ассет, нужен композитор или лицензия.

> Отдельно стоит упомянуть **колонию с автоматизацией (№2)**: у неё самый большой рынок, но и самый большой объём
> работ. Её лучше брать вторым проектом.

## 6. Риски и как с ними работать

| Риск | Решение |
|---|---|
| Раздувание объёма (scope creep) | Жёсткие критерии этапов, список «НЕ делаем в 1.0» |
| Нет «фана» в ядре | Серый прототип и плейтесты до любого арта; готовность к pivot |
| Несогласованный визуал | Вертикальный срез как эталон, ограниченная палитра, стайл-гайд |
| Падение производительности | Бюджеты кадра, профайлинг каждую неделю, пулы объектов |
| Игру никто не увидит | Маркетинг с этапа 2, страница Steam заранее, регулярные GIF |
| Баланс | Телеметрия + автосимуляции забегов |
